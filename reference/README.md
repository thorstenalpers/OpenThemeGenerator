# Reference project

A page with no framework, no build step, and no dependencies. Open `index.html` in a browser.

It exists to check one claim: that a theme generated by OpenThemeGenerator works outside Svelte,
outside Tailwind, and outside shadcn. `styles.css` never names a colour — every value is a
`var(--token)` from `theme.css`, so replacing that one file re-themes the whole page.

## Using your own theme

1. In the app, open **Export** and pick the **Plain CSS variables** format.
2. Write it into this folder, or copy `theme.css` over the one here.
3. Reload the page.

Besides the colours, `theme.css` carries the structural half of the theme — `--spacing-base`,
`--font-size-base`, `--border-width`, `--elevation-*`, `--sidebar-width`, `--container-max` — and
`styles.css` reads those the same way it reads the colours. A denser theme tightens this page
without either file changing.

To regenerate the checked-in file from a built-in preset instead:

```bash
node scripts/write-reference-theme.mjs violet
```

## Light and dark

`theme.css` declares three states, and the toggle in the header drives them:

| State                        | How it is set                                   |
| ---------------------------- | ----------------------------------------------- |
| Follow the operating system  | no `data-theme` attribute on `<html>` (default) |
| Always light                 | `<html data-theme="light">`                     |
| Always dark                  | `<html data-theme="dark">`                      |

The dark block is guarded with `:root:not([data-theme='light'])`, so a page pinned to light stays
light on a machine that prefers dark.

## Copying this into another project

`styles.css` is a starting point, not a library — take the parts you need. The only thing worth
keeping intact is the rule it follows: components read tokens, and nothing else declares a colour.
